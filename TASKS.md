# NIKASS — задачи первой части: товары и локальная корзина

## Цель

Собрать публичную товарную часть сайта в `website` на Astro + React:

`Главная → Каталог → Карточка товара → Корзина`

Все данные пока локальные и демонстрационные. Внешние сервисы, backend и
реальный заказ подключаются отдельным следующим этапом.

## Границы первой части

Входит:

- пять категорий из PRD: зарядные станции, Power Bank, солнечные панели,
  инверторы и AGM-аккумуляторы;
- карточки товаров и варианты внутри карточки;
- поиск, категории, фильтры и сортировка;
- страница товара с характеристиками и связанными товарами;
- анонимная корзина в рамках текущей вкладки;
- адаптивная вёрстка для смартфона и компьютера;
- локальные mock-данные и локальные изображения-заглушки.

Не входит:

- WooCommerce, WordPress, Hono, API, база данных и синхронизация;
- реальные остатки, проверка цены и создание заказа;
- регистрация, личный кабинет и полноценный checkout;
- онлайн-оплата, СДЭК, email и Telegram;
- импорт CSV/Excel и админка;
- AI, блог и формы заявок, если они не нужны для демонстрации товарного пути.

## Задачи

- [x] Зафиксировать в `CHECKLIST.md`, что текущий первый продуктовый этап —

- [x] Отметить локальный каталог и локальную корзину как активные части текущего

- [x] Оставить backend, WooCommerce, checkout и внешние интеграции отложенными.
- [x] Не удалять старые `/uk/*` Apple-маршруты до отдельного решения; они не

Готово, когда ограничения этапа записаны в durable-документации и не требуют
додумывания во время реализации.

### 1. Подготовить локальную модель и mock-каталог

- [x] Завести типы `Product`, `ProductVariant`, `Category`, `Availability` и

- [x] Хранить цену числом в рублях; форматировать её только при выводе.
- [x] Для каждого товара задать: slug, SKU вариантов, название, категорию,

- [x] Добавить небольшой набор данных, покрывающий все пять категорий и

  недоступный товар.
- [x] Использовать только локальные ресурсы; не добавлять fake API или
  неиспользуемый слой-адаптер.

Готово, когда каталог можно полностью отрисовать без backend и в данных есть

Готово, когда пользователь с любой товарной страницы может попасть в каталог,

Текущий срез включает общую шапку, подвал, полноценную mock-страницу товара и
рабочую локальную корзину без API и оформления заказа.

Готово, когда ссылка на товар открывает самостоятельную понятную страницу, а

### 5. Реализовать локальную корзину

- [x] Хранить в корзине только идентификатор товара/варианта и количество;
  цену и остальные данные получать из текущего mock-каталога.
- [x] Сохранять корзину в `sessionStorage`, а не в `localStorage`: она живёт
  при переходах и обновлении страницы, но исчезает после закрытия вкладки.
- [x] Использовать версию формата хранения и безопасно обрабатывать пустое,
  повреждённое или устаревшее значение.
- [x] Повторное добавление того же варианта объединять в одну строку и
  увеличивать количество.
- [x] На странице `/cart` показать изображение, товар, вариант/SKU, цену,
  количество, сумму строки и общую сумму.
- [x] Добавить изменение количества, удаление позиции и очистку корзины.
- [x] Синхронизировать счётчик в шапке между страницами внутри текущей вкладки
  через native browser events; вкладки не перезаписывают друг другу
  `sessionStorage`.
- [x] Обработать пустую корзину и вариант, который больше недоступен в mock-
  данных.
- [x] Не добавлять оплату и отправку заказа; кнопка следующего шага должна
  быть явно отключена или обозначена как функция следующего этапа.

Готово, когда пользователь может добавить разные варианты, перейти на другую
страницу, изменить количество, удалить позицию и увидеть корректную mock-сумму.

Готово, когда основной путь не ломается на мобильном и десктопе и доступен без

## Следующий этап после mock

После приёмки этой части отдельно спроектировать и подключить backend/API:

1. публичный контракт товаров и вариантов;
2. источник данных WooCommerce;
3. кэш каталога до пяти минут;
4. повторную проверку цены и доступности перед заказом;
5. единый checkout в `webapp` и передачу туда анонимной корзины.

До этого этапа не добавлять API-вызовы, фальшивую проверку остатков или форму
создания заказа в `website`.
