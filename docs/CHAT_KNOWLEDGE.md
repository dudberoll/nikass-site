# База знаний консультанта NIKASS

Консультант получает базовую инструкцию из `backend/src/modules/chat/application/knowledge-base.ts`.
Она составлена по снимку каталога и 872 вопросам/ответам из
`ozon_nikass_questions_answers.jsonl`. Выгрузка — источник типовых тем, но не
замена актуальной карточке товара или инструкции: в ней встречаются
противоречия, например по мощности солнечной панели 5370712388.

## Оплата, доставка и возврат

В системную инструкцию включены условия из `website/src/pages/payment-and-delivery.astro`
и `website/src/pages/return-policy.astro`: способы оплаты, условная оплата при
получении, работа с организациями, обработка и отправка, отдельная стоимость
доставки, приёмка оборудования, возврат качественного и дефектного товара,
гарантия, порядок обращения, расходы на обратную доставку и возврат денег.
Эти условия имеют приоритет над ответами покупателей из выгрузки. При изменении
страниц обновляйте этот раздел в `knowledge-base.ts` вместе с ними.

Чат объясняет опубликованные условия, но не проверяет статус заказа, не считает
тариф СДЭК, не принимает заявку на возврат и не перечисляет деньги. Конкретный
заказ и спорные случаи передаются менеджеру через контакты магазина. Указанные
на странице ограничения возврата и срок «до 10 рабочих дней» не подаются как
безусловный отказ покупателю или полный перечень его законных прав.

## Длина диалога

Сайт отправляет всю историю текущего чата в каждом запросе. API принимает
до 200 сообщений пользователя и консультанта вместе: это до 100 вопросов
с ответами. Лимит JSON-запроса по умолчанию — 512 КиБ
(`CHAT_BODY_LIMIT_BYTES=524288`); при больших репликах он может наступить
раньше лимита по количеству. В существующих окружениях с явно заданным
старым значением `131072` нужно обновить эту переменную и перезапустить API.

Реплика пользователя ограничена 4 000 символами, ответ консультанта — 12 000.
История принимает ответы той же длины, которую сервер разрешает вернуть.
История не сокращается автоматически и не сохраняется на сервере; после
достижения лимита пользователь начинает новый чат.

Общий виджет доступен на публичных страницах сайта в правом нижнем углу,
кроме `/cart` и `/checkout`. Переписка и текстовый черновик хранятся в
`sessionStorage` текущей вкладки и восстанавливаются при переходах,
возврате назад и обновлении страницы. Закрытие или сворачивание окна
не очищает диалог; «Начать новый чат» очищает его вместе с черновиком.
Полученный ответ сохраняется целиком до завершения анимации печати.
Если перейти на другую страницу до получения ответа, сохраняется вопрос;
запрос не повторяется автоматически. Аудиозаписи не сохраняются в браузере.
При недоступном хранилище интерфейс предупреждает о возможной потере переписки.

## Карточки товаров в чате

На финальном этапе рекомендации консультант добавляет от одной до трёх
ссылок на отдельной строке в формате Markdown. Интерфейс скрывает эти строки
из текста и превращает только разрешённые ссылки из `knowledge-base.ts` в
мини-карточки с актуальными данными каталога.

## Расчёт запаса энергии

Для станции, работающей через розетку 220 В, используется консервативная
оценка:

```text
требуемые Wh = Σ(мощность устройства, W × время, ч × количество), когда время указано
доступные Wh ≈ ёмкость станции, Wh × 0,85 × 0,85
время для постоянной нагрузки ≈ доступные Wh / суммарную мощность, W
```

Первые 0,85 учитывает неполный полезный разряд, вторые 0,85 — потери
инвертора. Расчёт проверяет одновременно:

- энергию за весь сценарий (`требуемые Wh ≤ доступные Wh`), только если длительность дана для каждого устройства;
- пиковую нагрузку (`ΣW ≤ номинальной мощности станции`);
- отсутствие входных данных. При нехватке `Wh` станции или `W` устройства бот задаёт уточняющий вопрос и не подставляет «среднее» значение. Без времени он всё равно может вернуть `runtimeHours` для постоянной нагрузки, но не выдаёт `fits` для сценария «на N часов».

Если номинальный выходной лимит станции неизвестен, `outputLimitExceeded` и
`fits` остаются `null` (если энергия сама по себе не доказала нехватку), а
`stationMaxOutputW` добавляется в список недостающих данных. Runtime-оценка при
этом не блокируется.

Пусковые токи холодильников, насосов, компрессоров и другой техники с
двигателем в эту простую оценку не входят. Для такой техники бот просит
номинальную и пусковую мощность и не обещает запуск по одному номиналу.

## Когда используется tool use

Калькулятор `calculate_energy_budget` предлагается только для последнего
сообщения, где одновременно есть намерение узнать запас/время работы и
контекст станции или нагрузки. Для справочных вопросов (комплектация,
назначение, правила подключения) запрос отправляется без инструмента.

После вызова результат калькулятора возвращается модели отдельным сообщением
`role=tool`; модель формулирует итог и показывает допущения. Включён только
один последовательный вызов (`parallel_tool_calls=false`), чтобы не запускать
инструменты без необходимости и не давать модели считать арифметику.

Провайдер не принимает и не исполняет произвольные имена функций: разрешён
только `calculate_energy_budget`, аргументы разбираются как JSON и проходят
валидацию в чистом TypeScript-калькуляторе.

## Beget AI Gateway

Чат использует OpenAI-совместимый endpoint
`https://api-llm.beget.com/v1/chat/completions`; локально выбраны `gpt-6-luna`
и серверный `AI_API_KEY`. В [руководстве Beget](https://beget.com/ru/kb/manual/ai-gateway)
описаны этот endpoint, совместимость с OpenAI и смена подключения через адрес,
ключ и имя модели. Каталог моделей меняется; актуальный список доступен через
`GET /v1/models`.

Beget рекомендует задавать `max_tokens`, чтобы шлюз мог оценить стоимость
запроса до отправки. Backend ограничивает ответы 512 токенами.

Текущая обработка калькулятора использует OpenAI tool-call формат
(`tools`, `tool_choice`, `tool_calls`, `tool_call_id`). В публичном руководстве
Beget не описана поддержка tool calling, поэтому работу калькулятора с выбранной
моделью нужно подтвердить отдельным живым запросом.

Голосовой ввод пока распознаётся отдельно через Cloud.ru Whisper endpoint.
Для сохранения этой функции заданы отдельные `AI_TRANSCRIPTION_URL` и
`AI_TRANSCRIPTION_API_KEY`; ключ чата Beget туда не отправляется.
